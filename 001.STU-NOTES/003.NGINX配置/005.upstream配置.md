## 1. keepalive N:后端连接复用池

请求结束不关后端连接,放入空闲队列下次复用:

```
指令          upstream 里 keepalive 256;
数据结构      ngx_http_upstream_keepalive_module.c
              max_cached 字段 :14,cache 空闲队列 :19
归属          队列挂在 server 级配置结构里——fork 后各 worker 私有
              → 每 worker 最多缓存 N 条,集群总缓存 = N × worker 数
```

收益:省掉每请求的 TCP( + TLS)握手与慢启动。对建立连接成本高的后端
(HTTPS 后端、跨机房 RTT 大),常常是反向代理链路收益最大的单项。
同时从根上缓解两个系统层压力:出站端口耗尽(`ip_local_port_range`)与
TIME_WAIT 堆积(不再需要 `tcp_tw_reuse` 对症,002 篇联动表)。

**生效前提**——1.30 起已默认满足,老版本(≤1.29)才需要显式配:

```
1.30.0 行为变更(CHANGES 确认):
  · upstream 的 keepalive 默认启用(未写指令时 = keepalive 32 local,
    init_main_conf 里置 max_cached=32、local=1,:552-555)
  · proxy_http_version 默认已是 1.1(ngx_http_proxy_module.c:4007-4008)
  · 默认不再发送 Connection 请求头
→ 老版本的经典三件套(1.1 + 清 Connection 头)在 1.30.2 上写不写都对;
  显式写只剩"声明意图"的价值

local 参数(1.30 新增,:610-612):keepalive 64 local
  local 模式下只复用"本 upstream 配置自己建立"的连接(:236),
  行为更保守;对非本地的后端建议显式写 keepalive N 覆盖默认的 32
```

配多大的 N:估算"每秒新建后端请求数 × 平均请求时长"的稳态乘积,
再按每 worker 摊;观察 `ss` 到后端的 established 与后端侧连接复用率。

## 2. zone:共享的是状态,不是连接池

```
upstream backend {
    zone backend_zone 1m;    # server 定义 + 运行状态进共享内存
    server 10.0.0.1:8080;    # round-robin 的选中/失败计数、
    server 10.0.0.2:8080;    # 慢启动/失败摘除状态跨 worker 一致
}
```

keepalive 的连接池在 worker 私有内存(§1);zone 让所有 worker 看到**同一份
后端健康状态**,并支持 API 动态修改 upstream(`zone` + `state` 文件)。
两者经常同时出现,但职责不同。

## 3. 连接寿命三参数

与客户端侧 keepalive 族(002 篇)对称,后端连接也有寿命管理:

```
keepalive_time     单条后端连接的总寿命(默认 1h),到龄重建,防碎片累积
keepalive_timeout  后端连接空闲多久回收(默认 60s)
keepalive_requests 单条后端连接最多服务多少请求(默认 1000)
                   —— 后端侧的对应限制要对齐,别 nginx 攒着连接而后端先踢
```
