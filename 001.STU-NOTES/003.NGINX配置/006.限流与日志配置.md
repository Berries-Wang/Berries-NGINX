# 限流与日志配置

> 源码根目录:`000.SOURCE_CODE/NGINX-1.30.2`。
> 限流挂在 HTTP 处理第 5 阶段 PREACCESS(架构笔记第 4 节),在进入 CONTENT 之前把流量挡掉。

## 指令速查表

| 指令 | 层 | 默认值 | 源码 | 一句话 |
|---|---|---|---|---|
| limit_req_zone | http | — | ngx_http_limit_req_module.c | 声明漏桶(共享内存) |
| limit_req | http/server/location | 不限 | 同上(:248 调用 lookup) | 应用漏桶,rate/burst/nodelay |
| limit_conn_zone / limit_conn | http / loc | 不限 | ngx_http_limit_conn_module.c | 并发连接数上限 |
| access_log | http/server/location | logs/access.log | ngx_http_log_module.c | 支持 buffer=/flush= |
| error_log | main/http/server/location | logs/error.log error | — | 高频路径砍级别立竿见影 |

---

## 1. limit_req:漏桶

```
声明    limit_req_zone $binary_remote_addr zone=req:10m rate=100r/s;
        key 用 $binary_remote_addr(4 字节)比 $remote_address 省内存;
        10m 共享内存约存 16 万个状态节点
应用    limit_req zone=req burst=200 nodelay;
```

核心漏桶公式(`ngx_http_limit_req_lookup`,节点状态存共享内存红黑树,跨 worker 一致):

```c
/* src/http/modules/ngx_http_limit_req_module.c:454,ms = 距上次访问的毫秒数 */
excess = lr->excess - ctx->rate * ms / 1000 + 1000;
/*                     └─ 按速率漏水 ──┘   └ 本次请求 +1 桶(1000=‰单位) */

if ((ngx_uint_t) excess > limit->burst) {
    return NGX_BUSY;            /* 超过桶容量 → 503 */
}
```

```
rate=N r/s    ctx->rate 以 ‰ r/s 为单位换算,即每毫秒漏 N/1000 个请求
burst         桶容量:允许的瞬时突发放行量
nodelay       突发请求立即放行(占用 burst 名额)而非排队等 delay
delay=N       (1.15+)只对超出部分的请求延迟 N 毫秒,平滑而不一刀切
状态共享      limit_req_zone 的 zone 在共享内存(slab),所有 worker 看到同一桶
```

定位:限流不是"让系统更快",而是在到达容量顶点前**主动丢车保帅**,
避免 accept 队列、fd、内存被无差别打穿(与架构笔记 7.2 的三条内核层防线互补)。

## 2. limit_conn:并发连接数

```
limit_conn_zone $binary_remote_addr zone=conn:10m;
limit_conn zone=conn 20;        # 每 key 最多 20 条并发连接
```

只统计**正在处理**的连接(请求计数归零即释放),keepalive 空闲连接不占名额。

## 3. 日志:高频路径的减负三招

### access_log 缓冲写

```
access_log /var/log/nginx/access.log buffer=32k flush=1s;
```

```
:324-328  日志先写进 buffer,放不下才触发立即落盘
:111-112  ngx_http_log_flush + 定时器事件,flush= 到点强制刷盘
效果      每条日志一次 write 系统调用 → 攒 32k 或 1 秒一次
```

### error_log 级别

默认 error;生产常调 warn。每条日志一次格式化 + write,
高频路径(accept、收发)上砍级别,收益不亚于任何业务参数。

### timing 日志格式(观测用,配合 007 篇方法论)

```
log_format timing '$remote_addr [$time_local] "$request" '
                  '$status $request_time $upstream_connect_time '
                  '$upstream_header_time $upstream_response_time';

$request_time              整个请求耗时    注册:src/http/ngx_http_variables.c:312(实现 :2269)
$upstream_connect_time     与后端建立连接耗时 ┐
$upstream_header_time      收到后端响应头耗时  ├ 注册:src/http/ngx_http_upstream.c:416-425
$upstream_response_time    后端总耗时          ┘(实现 :165,同一函数按标志区分)

差分诊断:request_time 高 + upstream_response_time 低 → 慢在 nginx/客户端;
         upstream_response_time 高 → 慢在后端,调 nginx 无用
```

极端场景 `access_log off` 前先确认可观测性缺口(至少留一台采样节点)。
