## 1. listen 参数与两条内核队列

backlog 与 somaxconn 的关系是**内核取 min**:

```
 客户端 SYN
     │
     ▼
 ┌─────────────────────┐
 │ 半连接队列(SYN_RECV)│   ← 上限:net.ipv4.tcp_max_syn_backlog
 └──────────┬──────────┘    三次握手在此完成
            │ 握手完成,挂入全连接队列
            ▼
 ┌─────────────────────┐
 │ 全连接队列(ACCEPT)  │   ← 上限:min( listen 的 backlog 参数, somaxconn )
 └──────────┬──────────┘       nginx 默认 511 │ 内核默认 somaxconn 4096
            │                   → 实际生效 511,只调 somaxconn 没用!
            │ EPOLLEXCLUSIVE 只唤醒一个 worker
            ▼
          accept()                    ngx_event_accept.c:21
```

```
nginx 默认 backlog   #define NGX_LISTEN_BACKLOG 511   src/os/unix/ngx_linux_config.h:115
生效调用             listen(s, ls[i].backlog)          src/core/ngx_connection.c:684
显式指定             listen 80 backlog=8192;           解析:ngx_http_core_module.c:4121-4132
```

**正确姿势(两头一起动)**:`listen 80 backlog=8192;` + `sysctl net.core.somaxconn=8192`。
现代内核 somaxconn 默认 4096,瓶颈通常在 nginx 侧的 511。

### reuseport:内核层连接分发

```
listen 80 reuseport;    解析:ngx_http_core_module.c:4225
配置期   ngx_clone_listening(src/core/ngx_connection.c:99)按 worker 数克隆监听
master   为每份各开一个 socket(SO_REUSEPORT)
worker   只挂自己那份进 epoll(src/event/ngx_event.c:808-810)
内核     按四元组哈希分流新连接 → 无惊群、无锁、各 worker 均衡
```

官方实测高连接速率场景约 3 倍吞吐提升;reload 时 worker 数变化会重建 socket
(存量连接不受影响)。可与 backlog= 同用。

## 2. keepalive 族:连接寿命的四个旋钮

keepalive 不是开关,而是一段有源码生命周期管理的"连接休眠"。
入口判定在 `ngx_http_core_module.c:1362-1370`(三重判定,任一不满足 → 关连接):

```
 响应发送完毕,进入收尾
     │
     │ ① keepalive_timeout > 0
     │ ② c->requests < keepalive_requests
     │ ③ 连接年龄(now - c->start_time)< keepalive_time
     ▼ 全部满足
 ngx_http_set_keepalive                       request.c:3257
   · 释放请求头大缓冲 hc->free / hc->busy(:3395-3417)
   · rev->handler = ngx_http_keepalive_handler(:3426)    ← 状态机换防
   · ngx_add_timer(rev, keepalive_timeout)(:3476)        ← 挂空闲定时器
   · ngx_reusable_connection(c, 1)(:3463)                ← 标记可复用
     │
     ├─ 空闲到点无新请求 → keepalive_handler(:3485)
     │                      → ngx_http_close_connection(:3514)
     │   ← 空闲期间一直占连接槽和 fd:keepalive_timeout 与内存/fd 联动的根源
     └─ 新请求到达 → 回到解析,c->requests++(request.c:544)
          ← 计数达到 keepalive_requests 后,最后一个响应带 Connection: close
```

各旋钮含义:

| 旋钮 | 默认 | 管什么 | 调优边界 |
|---|---|---|---|
| keepalive_timeout | 75s | 连接最多"白等"多久 | 浏览器场景 75s 合理;纯 API/内存紧张可 15-30s;**必须短于前置 LB 空闲超时**,否则 LB 先踢出 RST |
| keepalive_requests | 1000 | 每连接最多复用多少个请求 | 防长命连接累积碎片、绑定单 worker;一般不动 |
| keepalive_time | 1h | 连接年龄上限(请求数未到也关) | 与 requests 组成双重寿命 |
| keepalive_min_timeout | 不设 | 1.26+ 两段式:min_timeout 内不标 reusable(保底不被回收),之后才可回收,总时长到 keepalive_timeout 才真关 | LB 空闲超时较长时兜底(:3461-3474) |

## 3. sysctl 联动表(勘误沉淀为"常见误区")

| sysctl | 常见误区 | 正确理解 |
|---|---|---|
| net.core.somaxconn | "调大就行" | 生效值 = min(nginx backlog 默认 511, somaxconn),必须配 `listen ... backlog=`(§1) |
| net.ipv4.tcp_max_syn_backlog | 与 accept 队列混谈 | 它管**半连接**队列;SYN 突发/防护场景调大,不是 accept 容量 |
| net.ipv4.ip_local_port_range | 写成 `102465535`(丢空格) | `1024 65535`;nginx 作为客户端连接 upstream 时耗本地端口 |
| net.ipv4.tcp_tw_reuse | 当通用并发参数 | 只作用于**主动 connect 出站**(反向代理 → upstream)方向的 TIME_WAIT 复用,依赖 tcp_timestamps;入站无效;治本是 upstream keepalive(005 篇) |
| fs.nr_open | 忽略 | nofile 的绝对天花板,百万 fd 前先抬它(001 篇 fd 链) |

tcp_tw_reuse 的两个方向(TIME_WAIT 只发生在主动关闭方):

```
入站:客户端 ──► nginx(keepalive 超时后 nginx 主动关)
      nginx 侧产生 TIME_WAIT —— tcp_tw_reuse 管不了(它只作用于 connect())
出站:nginx ──► upstream(每请求新建连接时主动 connect)
      端口耗尽时 tcp_tw_reuse=1 允许复用刚回收的端口(依赖 tcp_timestamps,
      Linux 默认开)—— 这是它唯一的受益场景;治本是 upstream keepalive(005 篇)
```
