## 1. 请求头缓冲:先小后大,按需增长

```
初始缓冲    accept 后第一个读缓冲就是 client_header_buffer_size:
            ls->post_accept_buffer_size = cscf->client_header_buffer_size
                                        src/http/ngx_http.c:1843
增长算法    ngx_http_alloc_large_header_buffer   request.c:1651
```

```
 ① 请求行/某一行本身超长
      (size_t)(r->header_in->pos - old) >= large_client_header_buffers.size
                                     → NGX_DECLINED(request.c:1677-1682)
      请求行超长 → 414 Request-URI Too Large
      头字段超长 → 400 "client sent too long header line"
 ② 有空闲缓冲 → 复用 hc->free 链(:1686-1694)
 ③ 已用数 hc->nbusy < num → 新分配一个 size(8k)缓冲(:1696-1713)
 ④ 4 个用完仍不够 → NGX_DECLINED → 400/414(:1716)
```

配置边界:

- 大多数请求头 < 1k,初始小、按需增长——内存开销与连接数解耦的关键设计;
- 调大 `large_client_header_buffers` 前先看日志里 400/414 的量与成因
  (长 Cookie 链、大 UA、JWT),内存成本 = 连接数 × 缓冲大小;
- 若大量小请求也被迫增长到 8k 档,可调大 `client_header_buffer_size`(如 4k)
  换一次增长路径,同样按内存权衡。

## 2. gzip:level 是 CPU 和带宽的交换

```
gzip_comp_level   指令 :135,合法域 1-9(:103 bounds),默认 1(:1109)
                 每请求在 worker 单线程上 deflateInit2/deflate(:626)
                 level > 6 压缩收益趋平、CPU 时间陡增;建议 4-6
gzip_types        默认类型表只有 text/html(:133,ngx_http_html_default_types)
                 → text/html 不用写进 gzip_types,写了反而重复
                 常补:application/json text/css application/javascript ...
gzip_min_length   小于该值的响应不压(压不动还可能更大),建议 1024 起步
gzip_vary on      响应加 Vary: Accept-Encoding,给中间缓存区分压缩/未压缩版本
gzip_proxied any  默认对带 Via 头的代理请求不压缩;反向代理场景常用 any 放开
```

定位:gzip 提升的是传输段(total - TTFB),代价是 TTFB 本身——带宽紧张压 level,
延迟敏感降 level,别两头都要。

## 3. proxy_cache / fastcgi_cache:磁盘缓存 + 共享内存索引

```
proxy_cache_path /var/cache/nginx keys_zone=one:10m max_size=1g
                 inactive=60m use_temp_path=off;
```

```
keys_zone   共享内存(slab 分配器,跨 worker 一致,架构笔记 7.7)存 key 索引
响应体       落磁盘文件(src/http/ngx_http_file_cache.c)
后台进程     master 额外 fork 的 cache manager(过期清理)/
             cache loader(启动预热)
             src/os/unix/ngx_process_cycle.c:26-28, 59-60
```

热点数据的真正大头是内核页缓存——keys_zone 给足、让页缓存自然升温,
比调大磁盘 max_size 更有效。`proxy_no_cache` / `proxy_cache_valid` /
`proxy_cache_key` 按路由颗粒度控制;fastcgi_cache 同构。
